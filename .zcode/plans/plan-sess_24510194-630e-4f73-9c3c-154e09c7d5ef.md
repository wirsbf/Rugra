# RwLock 性能瓶颈修复方案 (长期规划)

## 问题诊断 (已确认)

7 个函数 (myprogress, getparameter, glob_word, glob_set, glob_range, glob_url, next_url) 在 curl_decompile 中超时 (>60s)。

**根因**：`Arc<RwLock<Varnode>>` / `Arc<RwLock<PcodeOp>>` 数据模型
- src/ 共 **8373 次锁操作** (`.read()/.write().unwrap()`)
- ruleaction.rs 占 2670，ActionPool::apply (action.rs:495) 每个 op × 每个 rule 都重锁
- `VarnodeLocRef/DefRef/PcodeOpRef` 的 `Ord` 实现每次比较都 `.read().unwrap()` 重读字段 → BTreeSet 操作锁爆炸

**关键事实**：**所有访问单线程**。curl_decompile.rs:494 每函数 spawn 一个 worker 线程，整个反编译期间持有单个 `fd_arc.write()` 守卫；锁存在仅为满足 `Send + Sync` bound（`op.rs:269` 的 `Weak<RwLock<dyn FlowBlock + Send + Sync>>` + `funcdata.rs` 自引用 `Arc<RwLock<Funcdata>>`）。

**Ghidra 对照**：裸指针 `PcodeOp*`/`Varnode*` 零开销 (varnode.hh:69, op.hh:178)。`Arc<RwLock<...>>` 是移植时为满足 Rust 借用检查器引入的，**不是算法需求**。

## 分阶段执行方案 (每阶段独立可验证 + 立即提交)

### 阶段 1 — 测量基线 [必做, ~0.5h]
- 给 ActionPool::apply / ActionGroup::perform / ActionHeritage::apply 加 `eprintln!("[PERF]")` 时间戳（提交前删）
- 跑 `curl_decompile 2>perf_baseline.log`，记录超时函数的 Action 时间分布
- 产出：`docs/alignment_docs/PERF_BASELINE.md` 基线数据

### 阶段 2 — BTreeSet Ord 键缓存 [~2h]
**问题**：`VarnodeLocRef`/`VarnodeDefRef`/`PcodeOpRef` (varnode.rs:1667/1741, op.rs:1190) 是 `pub struct X(pub Arc<RwLock<...>>)`，`Ord` impl 每次比较 `.read().unwrap()` 重读。

**修复**：在 newtype 中缓存排序键 (loc/size/create_index/SeqNum)，这些键在生命周期内不可变。
```rust
pub struct VarnodeLocRef {
    pub vn: Arc<RwLock<Varnode>>,
    loc: Address,
    size: usize,
}
```
Ghidra 1:1 对齐 varnode.hh VarnodeLoc + varnode.cc:1300 VarnodeCompare (带键副本，无锁)。

**收益**：BTreeSet 操作从 O(log n × 2 lock) → O(log n)。

### 阶段 3 — parking_lot::RwLock 平替 [~2h, 主要收益]
**修复**：`std::sync::RwLock` → `parking_lot::RwLock`。parking_lot 纯用户态、无 syscall、跨平台一致 (~20ns vs std SRWLOCK 可能的 kernel fallback)。

**任务**：
1. Cargo.toml 加 `parking_lot = "0.12"`
2. 全局替换 src/ 内 `std::sync::RwLock` → `parking_lot::RwLock`（不动 src/bin/rugra.rs 顶层 `Arc<RwLock<Funcdata>>` 跨线程需要）
3. 脚本批量删除 `.read()/.write()` 后的 `.unwrap()`（parking_lot 不返回 Result）
4. 处理 trait object `dyn FlowBlock + Send + Sync` 的 RwLock 切换
5. 排查 reentrant 嵌套（parking_lot 不可重入）

**收益**：预期 10-100× 速度提升，即使 2× 也能把 7 个超时降到 5s 内。

**验证**：`curl_decompile` 7 个超时全部完成；差分门禁 defects=0。

### 阶段 4 (可选) — 移除 self_ref 自引用 [~2h]
- 调研 `Funcdata.self_ref: Weak<RwLock<Funcdata>>` (funcdata.rs:86) 用法
- 改为传 `&Funcdata` 参数或 `*const Funcdata` raw pointer
- 解除 `Funcdata: Send + Sync` 要求，为阶段 5 铺路

### 阶段 5 (可选, 长期) — 完全单线程化 [~4-8h]
**方案 A** `Rc<RefCell<Varnode>>`：零锁开销 (~5ns)，删除 worker thread 改用 alarm timeout
**方案 B** arena 索引 `VarnodeId(usize)` + `Vec<UnsafeCell<Varnode>>`：完全匹配 Ghidra `vector<Varnode*>` 模型，最快但改动最大
