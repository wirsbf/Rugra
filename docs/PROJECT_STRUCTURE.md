# 完整的架构与项目结构 (Project Structure)

本文件概括讲述 `Rugra` 库内模块分布、核心数据流架构、CLI 工作机理以及各文档产物的分发结构。
此文档为 **项目总控级结构索引**。

---

## 源码模块纵览 (`src/`)

| 模块目录 | 核心组件职能 | 相关底层/依赖库 |
| :------- | :----------- | :-------------- |
| `analysis/` | CFG 图构建、数据与生命期分析、类型约束推断、SSA 生成及终版消除优化与聚合 | 高级 C-化还原算法 |
| `binary/` | 读取并分解 ELF/PE/Mach-O，加载其节段内存与导入/导出符号表。处理 PLT 重定位 | `goblin` |
| `codegen/` | （代码生成后端）提取 Analysis 表项构建结构化的高级语义 C 源码输出 | 内部 AST 表达器 |
| `pcode/` | 处理 P-code 块操作 `Program`，生成 `Varnode` 和带有版本控制与操作字 `PcodeOp` 的图节点 | Ghidra 启发的 IR |
| `translator/`| 将具体微操分解至 P-code，现只支持全映射 x86-64 | `iced-x86` |

---

## 辅助与输出矩阵 (`tools/` & `result/`)

| 辅助目录 | 职能范围 | 
| :------- | :----------- |
| `tools/` | 放置所有用于自动化对拍、P-code 导出、FFI 验证等乱七八糟环境辅助任务的外部脚本（如 `ghidra_export.py` 等）。 | 
| `result/pseudocode/` | 本地测试反编译的输出落地区。存放临时生成的 `.c` 源文件、报错日志（如曾经的 `curl_decompiled.c` 堆叠存放地）。绝对禁止将此类大块测试物料丢弃在项目主根目录。 |

---

## 文档及产物归档系统 (`docs/`)

所有的研究沉淀、进度评估、架构决策都必须按规定进入对应的文档槽内（各目录下均存在 `TEMPLATE.md` 指导范本）。

*   **`docs/api/`**: **全库架构的 API 1:1 分割对照字典**。根据 `src/` 文件严格层级生成的详尽接口参考书。
*   **`docs/AgentLog/`**: 人机协同开发日志本（AI 助手的每一次工程变更推进）。
*   **`docs/decisions/`**: ADR 架构决策库。记录所有产生影响的技术选用选型及退回理由。
*   **`docs/experiments/`**: 真实二进制数据的实验效果跑测、对拍比对率（命中率）日志。
*   **`docs/method/`**: 含有学术性、破局性算法论点的提纲与宣发主张。
    *   **`docs/method/impl/`**: 伴生上级观点，展开谈其实际硬编码在 RustVSR/Rugra 内的工程映射。
*   **`docs/workflow/`**: 代码隔离、错误修复或对齐工作流的 Checklist 单子指引文件。
*   **`docs/branches/`**: （非 master 隔离状态跟踪）开发分支挂起状况单。
*   `data_contract.md`: 全局数据进出/边界交换的类型规范契约。

## FFI 及测试对拍验证机制

请参看 `docs/VERIFICATION_GUIDE.md` 了解：
1. 本项目如何调用/依赖构建底层 C++ 的 Ghidra `sleigh/decomp` 组件来实现测试层面的 1:1 比拼。
2. 每次发布大更新前（尤其是对 `analysis/` 进行重构推演），需要进行的硬拦截门槛检测规则。
