## 模块定位

`src/bin/rugra.rs` 是当前 crate 的二进制入口文件，对应 Cargo 中声明的可执行目标 `rugra`。

但就当前代码状态而言，它**不是一个完整开放的命令行反编译前端**，而是一个**有意保持最小化的占位/提示入口**。  
其职责是：

1. 保留二进制入口位点
2. 向调用者明确提示当前 CLI 尚未恢复
3. 避免把尚未稳定的架构重构状态误包装成可直接使用的正式命令行产品

---

## 当前实现概览

当前文件中的实现极简，其行为可以概括为：

- 定义一个 `main()` 函数
- 运行时输出一条提示信息
- 提示内容说明：
  - Rugra CLI 当前暂时禁用
  - 原因与架构正在向 Ghidra 风格模型对齐有关

这意味着当前 `rugra` 二进制的真实行为是：

- **可以启动**
- **会输出说明信息**
- **不会提供完整子命令解析**
- **不会执行文档中旧版本曾描述的 `decompile` / `analyze` / `pcode` 等正式 CLI 工作流**

## 当前可确认行为

### `fn main()`

#### 作用
作为二进制入口运行，并输出一条说明性消息。

#### 当前语义
当前 `main()` 的语义不是“执行完整 CLI 流程”，而是：

- 明确告知用户当前 CLI 处于临时停用状态
- 将真实状态暴露给调用者
- 避免出现“程序能运行，所以功能也完整可用”的误解

#### 设计意图
这种最小入口通常用于过渡阶段，常见目的包括：

- 架构重构期间避免暴露不稳定接口
- 保留 Cargo 可执行目标
- 防止旧文档继续误导用户把 CLI 当成当前主入口
- 将用户引导回库级接口、示例程序或内部分析链路

## 这份文件当前**不负责**什么

当前 `src/bin/rugra.rs` **不负责**以下职责：

- 不负责参数解析
- 不负责子命令调度
- 不负责文件输入处理
- 不负责反汇编命令入口
- 不负责反编译命令入口
- 不负责打印 P-code
- 不负责生成结构化 C 输出
- 不负责验证流程入口
- 不负责作为当前稳定用户界面

如果其他文档仍把 `rugra` 二进制描述为完整 CLI 产品，应优先修正文档，而不是沿用旧说法。
