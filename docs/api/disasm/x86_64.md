### 2026-09-23：CONCATRAM-0001 — 段绝对寻址捕获（FS/GS prefix → fs_offset/gs_offset base）

`extract_operands` 的 `OpKind::Memory` 分支此前只读 `memory_base()`：
段绝对寻址（`64 48 8b 04 25 28 00 00 00` = `mov rax,fs:[0x28]`，canary 读取）
在 iced 报告 `base=None + segment=FS`，段前缀被丢弃后落入"绝对位移"折叠，
lift 成裸 `Ram@0x28` 内存读。现在 `base=None` 且 `segment_prefix()==FS/GS`
时把 base 置为 `"fs_offset"`/`"gs_offset"` 假名，由 `x86_lift::get_register`
解析到 x86-64.sla 的空间基址寄存器（FS_OFFSET=register:0x110:8 /
GS_OFFSET=0x118:8，probe 实测），lift 出 `INT_ADD(in_FS_OFFSET, disp)` 寻址 —
双基线（canon/direct golden）打印 `*(undefined8 *)(in_FS_OFFSET + 0x28)` 的形态。
判别器必须用显式 `segment_prefix()`（`memory_segment()` 无前缀时默认返回
DS/SS）。curl E2E 字节不变（主路径 SLEIGH）；httpd canary 家族
`iRam…28`/`uRam…28`（10 记号）清零。

### 内存操作数的段前缀提取(2026-09-23,LIFT-FS-CANARY-FORM-0001)

`extract_operands` 的 `OpKind::Memory` 臂从 iced 的
`Instruction::segment_prefix()`(非 `memory_segment()`——后者会补
DS/SS 默认段,长模式不适用)提取段前缀,仅映射
`Register::FS => "fs"`、`Register::GS => "gs"`,其余(CS/DS/ES/SS
前缀与无前缀)一律 `None`,填入 `Operand::Memory.segment`。
长模式下仅 FS/GS 前缀有架构语义,x86-64 SLEIGH 亦只为二者生成段基
寻址构造器。
