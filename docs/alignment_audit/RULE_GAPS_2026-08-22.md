### 1.4 池调度语义（正向确认）

Rugra `ActionPool::apply`（action.rs:503-563）忠实移植了 `ActionPool::processOp`（action.cc:822-875）的关键语义：dead-op 跳过、规则成功后 opcode 变化则从 rule_index=0 重启调度、以及 "changed op without returning result of 1" 错误消息（action.rs:548-556 ≈ action.cc:866）。残余差异：Rugra 在 pass 开始时快照 `obank.alivelist.clone()`（action.rs:508），Ghidra 用活迭代器可在同一 pass 内处理中途新建的 op——依赖 repeatapply 收敛时终态通常等价，但规则应用次序可能不同，记 UNTESTED（不单独立 TODO,并入各 Rule fixture 验收）。
