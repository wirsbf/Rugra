## 2. 四类语义逐项核对（复核清单 1）

### 2.1 CALL/CALLIND input 循环（slot≥1、annotation 跳过）— MATCH

Rugra（a95562f，src/coreaction.rs CALL/CALLIND 臂）：op 遍历内 `for slot in 0..num_input`，`input_vn.read().unwrap().is_annotation()` 跳过后经 trait dispatch 播种（CALL → `TypeOpCall::get_input_local`，CALLIND → `TypeOpCallind::get_input_local_in_fd`），每 seed 过 `merge_min_type_order`。

- 这是 Ghidra :5016 varnode 循环 + varnode.cc:921-924 descend 迭代的 **op 中心逆映射**：Ghidra 中 CALL input varnode 以 CALL 为 descendant（不满足 :5019 跳过条件），在其 getLocalType 内经 `inputTypeLocal(slot)` 播种；Rugra 反转遍历方向（op → input slot），被多个 CALL 读的 varnode 每次 min-merge，与 Ghidra 每 descendant 一次竞争等价。
- CALL slot0：Ghidra 中 fspec 常量是 annotation varnode，被 :5018 跳过，从不播种；Rugra 臂以 `is_annotation()` 跳过该 input —— 等价。且 `TypeOpCall::get_input_local` 内部 `slot==0 → fallback` 双保险（对齐 :695 前半）。
- CALLIND slot0：真实 code-pointer varnode（非 annotation）参与播种，走 :752-756 对应分支 —— fixture C5S0 双侧验证（ptr8 + canonical identity）。
- is_annotation 判定用的是 varnode flag（ANNOTATION = 1<<2，与 Ghidra `annotation` flag 对应）。

### 2.2 typeOrder-min merge（严格小于，平局保先播）— MATCH

`merge_min_type_order`（coreaction.rs:3638 附近）：`Entry::Vacant → insert`；`Entry::Occupied → ct.type_order(entry.get()) < 0 才替换`。逐字对齐 varnode.cc:926-931（`ct==0 → ct=newct`；`0>newct->typeOrder(*ct) → ct=newct`）。typeOrder 两侧同源（Rugra datatype.rs:1098 `ptr::eq 短路 + compare_at_level(10)`，A43 证据与本复核各自独立确认）。**平局保留 incumbent（先播者）**，与 Ghidra 语义一致。fixture C6（A6 先喂锁定 ptr→struct 的 C6A 再喂锁定 uint8 的 C6B → ptr8）覆盖跨 op 的 min 竞争（非平局方向性 case）。

### 2.4 UNKNOWN fallback（禁 INT/UINT）— MATCH

两侧 fallback 同为 `base_local_type = type_factory.get_base(size, TypeMetatype::Unknown)`（= typeop.cc:271-275）。臂内注释明示 "the INT/UINT `IntTypes` fallback must never replace it"；fixture C8（完全解锁参数 → canonical unknown4）验证 dispatch 路径上 IntTypes INT/UINT 不触发。此前的 output 臂亦统一改经 `merge_min_type_order`（OUT1 case 验证锁定输出 seed 过 min-merge）。

### 3.2 double-seed 判定：当前无

Ghidra 中 buildLocaltypes 是唯一播种点，getLocalType 是其内部调用（coreaction.cc:5026/:5029 → varnode.cc:900）。Rust 现状把这一数据流投影为两条路径：

### 3.3 语义缺口与重复实现（集成的真实调和点）

1. **A43 的 dispatch 表缺 CALLIND callspec 分支**：master `varnode.rs:302 op_input_type_local` 中 `(CPUI_CALLIND, 0)` 内联了 code-pointer 逻辑，但 **slot≥1 落入 `_` 兜底（metain/Unknown base）**——无 `getCallSpecs`/isTypeLocked/isThisPointer。A43 自己的 fixture metadata 如实登记："CALLIND parameter slots ... need parent->Funcdata; both fall to the Ghidra fc==null/bb==null base-default paths, which the fixture does not reach"。即 A43 路径下 CALLIND slot≥1 与 Ghidra :757-773 **不齐**（在其 fixture 不可达态下无害）。D2 的 `callind_input_local` 是该缺口的完整移植。
2. **min-merge 双实现**：D2 的 `merge_min_type_order`（coreaction.rs）与 A43 `get_local_type` 体内联竞争循环（varnode.rs）是 varnode.cc:926-931 的两个独立实现，语义等价（我两侧亲读比对：Vacant-insert/严格小于替换逐条一致）。
3. **tie-break 顺序源不同**：Ghidra 竞争固定为 def-output 先播 → descend 插入序（单次 getLocalType 调用内原子完成）；D2 主管线为"v_type 预播种（无条件 insert）→ op walk 按 alivelist 序 min-merge"。typeOrder 平局（同 submeta 同 size 的不同类型，如两个同尺寸具名 struct）时 incumbent 可能与 Ghidra 不同。该差异属 ACTION-INFERTYPES-DISPATCH-0001 已登记的结构残差（`varnode_centric_getlocaltype_structure: UNTESTED`），非 D2 引入的回归。
